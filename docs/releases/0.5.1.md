# ForgeFlow 0.5.1

Optional Codex project activation. **Additive**: the integration is opt-in, no
existing command changes behavior, and no migration is required. See
[Protocol Versioning](../../protocol/versioning.md) for the classification and
[Codex project activation](../codex-activation.md) for setup, update, and
rollback.

## What is new

* **`scripts/codex-activate`.** An explicit installer for an already-adopted
  repository. Run with no flag it previews the exact managed paths and the
  `AGENTS.md` diff and writes nothing; `--apply` installs. Exit `0` is a
  successful preview, a no-op, or a completed installation as stated in the
  output, `1` is a refusal or operational failure, and `2` is invalid
  invocation.
* **A repository-local `forgeflow` skill.** `.agents/skills/forgeflow/` holds
  `SKILL.md`, a copy of the canonical Story-development workflow, and a
  `.forgeflow-snapshot` identity file. Codex discovers it from the repository,
  so a development prompt no longer carries the ForgeFlow source path.
* **A bounded `AGENTS.md` section.** One managed block between
  `<!-- ForgeFlow Codex: begin -->` and `<!-- ForgeFlow Codex: end -->`. Every
  byte outside it is preserved, including CRLF line endings and an unterminated
  final line.
* **Explicit, pinned updates.** The snapshot records the integration version,
  the source revision, the adopted template version at installation, and POSIX
  `cksum` values for the owned content. Reapplying an identical snapshot is a
  no-op; an update is a deliberate choice of a newer checkout. There is no
  network fetch, no automatic upgrade, and no force flag.
* **A reproducible acceptance walkthrough.**
  `specs/stories/FF-225-codex-project-activation/walkthrough-fixtures.sh`
  builds the C1-C11 fresh-session fixtures in a new temporary directory. It
  never targets an existing adopter and never invokes Codex.
* **ADR-002.** [The decision record](../../specs/decisions/ADR-002-repository-local-pinned-activation-snapshot.md)
  states why activation is a repository-local pinned snapshot rather than a
  global skill or a runtime fetch.

## What did not change

`./scripts/bootstrap` and `--upgrade` keep their command forms and behavior; in
particular `--upgrade` still never reads or writes an adopter's `AGENTS.md` and
never installs this integration. The adoption marker format, Doctor verdicts,
`scripts/story-check`, `scripts/handoff-check`, `scripts/verification-check`,
and `make verify` semantics are unchanged. An adoption without the integration
stays valid, and a missing skill never invalidates one.

## Known limits

Installation is not proof that a given prompt will load the skill. Codex owns
instruction loading and skill selection, host overrides and instruction limits
apply, and `$forgeflow` remains the explicit fallback. The integration supplies
guidance, not tool interception or a mechanical gate.

The recorded checksums detect accidental drift; they are not a signature and do
not protect against someone editing an owned file and its recorded checksum
together. Like bootstrap, the installer assumes a quiet target: it is not a
sandbox against hostile concurrent writers and not a cross-file atomic
transaction under power loss or `SIGKILL`. Recovery preserves contents and
existence, not original inode identity.

`make verify` covers the deterministic installation, safety, and compatibility
cases. It does not certify model behavior; the C1-C11 walkthrough is human
review evidence recorded separately.
