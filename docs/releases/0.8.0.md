# ForgeFlow 0.8.0

`0.8.0` removes mutable lifecycle state from ForgeFlow's repository contract.
ForgeFlow defines Story intent, acceptance, architecture, execution and
verification contracts, plus immutable evidence. It does not store what state
the work is currently in.

## Breaking change

The Handoff Contract is now the Handoff Evidence Contract. A legacy block with
`workflow.current_story`, `next_story`, `completed_stories`, lifecycle status,
dirty-worktree projection, or last/current verification fails the new checker.
There is intentionally no compatibility parser because accepting both schemas
would preserve two current-state authorities.

The replacement records one historical observation:

```yaml
handoff:
  story: ABC-005
  recorded_at: 2026-09-12T02:30:00Z
  repository: owner/repository
  revision: 0123456789abcdef0123456789abcdef01234567

verification:
  command: make verify
  result: pass
```

Lifecycle states and transitions remain shared vocabulary. When an external
control plane is present it owns current work, lifecycle and Gate state, next
action, review state, verification-current state, and completion state.
ForgePilot is one example; `story-check`, `handoff-check`, Doctor, bootstrap,
and `make verify` do not require it.

## Upgrade

1. Move mutable workflow state into the control plane or direct human process.
2. Replace or remove the optional legacy handoff. Preserve a record only when
   its Story, UTC time, repository, exact committed revision, command, and
   result are known. Do not attach a dirty-worktree PASS to unchanged HEAD.
3. Reconcile repository-owned `AGENTS.md` and installed ForgeFlow skills so
   they do not infer current work from handoff or task notes.
4. Run `./scripts/handoff-check`, Doctor if used, and `make verify`.

Rollback must restore the `0.7.0` protocol, template, checker, and guidance as a
set. The new evidence record cannot reconstruct current, next, or completed
work; obtain those facts from their owning system.
