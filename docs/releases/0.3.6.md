# ForgeFlow 0.3.6

This compatible release combines an Additive optional readiness mode with
Corrective contract parsing and bootstrap reliability repairs. No migration is required.

* FF-217: Story tables recognize escaped pipes without stripping payload
  backslashes. All contract readers share backtick/tilde fence character and
  length rules; an unclosed fence ignores the rest of the file.
* FF-218: `scripts/story-check --ready` checks concrete Goal/Scope content and
  unique, nonempty checkbox AC IDs. Default checks and Doctor stay unchanged.
  Readiness is a minimum-content check, not human approval or a quality score.
* FF-219: Bootstrap stages all replacements and original backups before writing,
  commits the adoption marker last, and restores prior managed contents/existence
  on detected failures. Incomplete recovery identifies paths, retained backups
  and manual steps. `--upgrade` still leaves AGENTS.md alone; dry-run is read-only.
* FF-220: Separate behavior jobs cover macOS `/bin/sh` and Ubuntu `/bin/dash`,
  including actual child-script interpreters. Linux `make verify` remains the
  full canonical gate, including TypeScript, Go and Actions checks.

Bootstrap recovery is not a cross-file atomic transaction. Power loss, SIGKILL,
hostile concurrent writers, inode identity and hard-link reconstruction are not
guaranteed. Staging requires disk space and readable originals. See
[failure recovery](../upgrading.md#failure-recovery) for operational instructions.

Publication follows `docs/releasing.md`: clean committed readiness, exact-SHA CI,
annotated tag and verified GitHub Release. These notes alone do not assert that
publication or remote CI has completed.
