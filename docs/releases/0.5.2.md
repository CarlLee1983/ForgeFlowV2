# ForgeFlow 0.5.2

A vocabulary and scope correction. **Corrective**: no command form, result name,
exit status, or verdict changes, and no adopter migration is required. See
[Protocol Versioning](../../protocol/versioning.md) for the classification.

## What was wrong

`protocol/architecture.md` names the checks that would require analysing source
code and states that ForgeFlow does not implement them. Three things undermined
that statement.

`protocol/versioning.md` and [the 0.5.0 notes](0.5.0.md) restated the list as
"future extensions", which reads as deferred work rather than declined work.
Both restatements also dropped `architecture drift`, so the canonical list had
five entries and the restatements had four. `docs/code-quality.md` named the
same territory with a third vocabulary again.

The word "contract drift" meant two unrelated things in one repository: the
architectural sense, which is an exported interface changing between versions,
and Doctor's `CONTRACT_DRIFT` result, which reports adoption marker, Story,
handoff, and Guidance drift.

And the only test pinning any of it asserted the substring `dependency
direction`, which also occurs at an earlier, unrelated sentence in the same
file. The whole extension-point paragraph could be deleted with the suite still
green.

The practical consequence, observed on 2026-09-07: a reader took the list as a
gap to be closed and asked for the checks to be implemented. Nothing
distinguished "not built yet" from "deliberately not ours to build".

## What changed

* **One list, one vocabulary.** Dependency direction validation, forbidden
  imports, layer boundaries, public interface drift, and architecture drift are
  named identically wherever they appear, and no list drops an entry.
* **A boundary, not a schedule.** The live documents state that ForgeFlow does
  not implement these and does not intend to. They belong to the adopting
  repository, which places its own checker behind `make verify` and records the
  `architecture` layer as `unsupported` with a residual risk when it has none.
* **`public interface drift`.** The architectural sense is renamed and
  explicitly distinguished from Doctor's `CONTRACT_DRIFT`. Doctor's result
  value, meaning, and documentation are unchanged.
* **[ADR-003](../../specs/decisions/ADR-003-forgeflow-does-not-analyze-architecture.md).**
  The non-goal now has a decision record stating the boundary, what it costs,
  and the condition that would overturn it. A future request to implement the
  checks is a request to change that decision.
* **An assertion that holds.** `tests/execution-governance.sh` now requires the
  complete list and the sentence stating the position, and `FF226-AC-004` proves
  it on fixtures: the paragraph removed, the unrelated sentence alone, and a
  list with one entry dropped all fail.
* **Dead code removed.** `scripts/verification-check` no longer accumulates
  architecture decisions, boundaries, and owners into variables it never read.
  It validates the shape of each declaration; resolving them is
  `scripts/story-check`'s job.

## What did not change

Every checker keeps its command forms, result names, exit statuses, and
diagnostics. Doctor's verdicts, including `CONTRACT_DRIFT`, are untouched. The
Story and handoff contracts, verification profiles, and `make verify` semantics
are unchanged. [The 0.5.0 notes](0.5.0.md) are deliberately left as written:
they record what was said at that time, and the correction is stated here so
both remain readable.

## Known limits

This release changes what the documents say, not what the tooling does. The five
analysis checks remain unimplemented, now by stated decision rather than by
omission. A repository that wants them still has to build or adopt them itself,
and a high-risk Story in a repository without one still records
`architecture: unsupported` and stays PARTIAL.
