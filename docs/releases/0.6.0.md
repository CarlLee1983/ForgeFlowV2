# ForgeFlow 0.6.0

One Story ID grammar, enforced where a Story is created. **Breaking**: a
repository holding a Story whose directory does not name a conforming Story ID
sees a new `scripts/story-check` failure. See
[Protocol Versioning](../../protocol/versioning.md) for the classification.

## What was wrong

`scripts/story-check` and `scripts/handoff-check` disagreed about what a Story
ID is. `story-check` never looked at a Story's directory name. `handoff-check`
required a prefix, a hyphen, and digits, because it read everything after the
*first* hyphen and required it to be numeric.

A Story ID carrying a subsystem segment therefore passed the Story Contract and
could never appear in a conforming handoff. The failure surfaced when the Story
was recorded as complete, which is the point where the ID is most expensive to
change.

This was not hypothetical. A read-only survey of the three adopting
repositories on 2026-09-07 found `Dbcli` carrying eight such Stories,
`DBCLI-PLAT-001` through `DBCLI-PLAT-013`. Each passed `./scripts/story-check`;
each was rejected by `./scripts/handoff-check` with `completed Story is not a
Story ID`.

The grammar was also stated in one place only, the Handoff Contract. The
document that tells an author how to name a Story said nothing about the rule
that would later reject it.

## What changed

* **One grammar, stated twice.** A Story ID is hyphen-separated segments of
  uppercase letters and digits: the first segment starts with an uppercase
  letter, each middle segment has an uppercase letter, and the last segment is
  digits. [The Story Contract](../../protocol/story.md) and [the Handoff
  Contract](../../protocol/handoff.md) state it identically.
* **`handoff-check` accepts subsystem segments.** `DBCLI-PLAT-001` is now
  recordable as a current, next, or completed Story.
* **`story-check` validates the ID.** A Story whose directory does not name a
  conforming ID fails the Story Contract, reporting the directory and the
  grammar, so the problem surfaces when the Story is written.
* **The two checkers are tested against each other.** `tests/story-check.sh`
  `FF227-AC-005` feeds one shared corpus to both and fails the build if either
  accepts what the other rejects. Proving each checker correct in isolation is
  how the original disagreement survived.

The grammar is only loosened. `FF-1-2` stays rejected: a bare number is not a
subsystem name, and the pinned corpus in `tests/handoff-check.sh`
`FF212-AC-004` keeps every verdict it had.

## Migration

Run this in your repository:

```sh
./scripts/story-check
```

A Story whose directory does not name a conforming ID reports `Story directory
does not name a Story ID`, naming the directory, the ID it was read as, and the
grammar. There are two distinct causes, with two different repairs.

**The ID itself does not conform.** Rename that Story's directory under
`specs/stories/` to a conforming ID and update every reference to it, including
`specs/handoff.md`.

**The ID conforms but the slug was absorbed into it.** The directory name is
the ID followed by an optional slug, and the ID is the leading run of segments
made only of uppercase letters and digits. A slug segment written that way is
read as part of the ID: `FF-232-API-limits` reads as `FF-232-API` and
`FF-115-3-way-merge` reads as `FF-115-3`, and both fail even though `FF-232`
and `FF-115` are perfectly good IDs. Here the repair is to reword the slug —
`api-limits`, `three-way-merge` — which leaves the ID and every reference to it
untouched. Do not rename the Story.

The diagnostic tells the two apart: it prints the ID it read, so a reported ID
that is not the one you meant is the second case.

Scope of what was checked: the 2026-09-07 survey covered the three adopting
repositories known to this project. It compared Story IDs against the two
grammars, and found no ID that the new grammar rejects. It did not run the new
directory-name extraction over those repositories, so it does not bound the
slug-absorption case above — and three repositories are not a verified
population in any event. Run the command rather than relying on this result.
