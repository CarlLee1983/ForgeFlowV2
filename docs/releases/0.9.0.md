# ForgeFlow 0.9.0

`0.9.0` simplifies the repository adoption contract. ForgeFlow defines
capabilities and structural invariants, not a complete inventory of files a
starter layout happens to install.

## Required and structural

The required entrypoints are `AGENTS.md`, `Makefile` exposing `make verify`,
and `specs/stories/`. Each ready Story lives under that root with `story.md`
and `acceptance.md`; `task.md` and additional Story-owned artifacts are
optional.

## Optional capabilities

Guidance, immutable Handoff evidence, Skills, CI, templates, and
repository-specific extensions are optional. Doctor reports their detection
without treating absence as `STRUCTURE_INCOMPLETE`. Guidance, when present, is
validated from `guidance/ENTRY.md`; the four Guidance documents bootstrap seeds
are a customizable starter layout, not a permanent protocol inventory.

## Bootstrap and upgrade

Bootstrap still uses an internal source-to-destination manifest to install its
opinionated starter. That manifest is installer ownership, not conformance.
Upgrade continues to manage only the Story template and adoption marker; it
does not restore repository-owned optional Guidance.

This release is Breaking only for consumers that parse Doctor's former
`Guidance:` status values. Map `OPTIONAL_LEGACY` to `NOT_PRESENT` and
`GUIDANCE_BASELINE_OK` to `GUIDANCE_CONTRACT_OK`. Split the former
`GUIDANCE_INCOMPLETE` case by cause: a missing or blank `ENTRY.md` becomes
`GUIDANCE_CONTRACT_INCOMPLETE`, while a missing or blank non-entry starter
document becomes `GUIDANCE_CONTRACT_OK`; an unsafe `ENTRY.md` remains `ERROR`.
A legacy `ERROR` caused only by a symlinked, wrong-type, or unreadable
non-entry starter document becomes `GUIDANCE_CONTRACT_OK`. Repository adoption
itself needs no file migration: optional layouts remain valid. Run Doctor if
used and `make verify` after choosing any desired repository-specific updates.
