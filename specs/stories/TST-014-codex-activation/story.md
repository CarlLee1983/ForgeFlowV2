# Story: TST-014 Codex Activation

## Goal

Deliver `forgeflow codex activate` preview and apply so an adopted repository
can install or update the existing bounded project-local Codex integration with
deterministic ownership, drift detection, snapshot-last mutation, and
actionable recovery evidence.

## Context

GitHub issue #39 follows TST-013's content-addressed Init planning and mutation
evaluation. The retained `scripts/codex-activate` is the behavioral
compatibility oracle. This Story migrates its installation capability into the
TypeScript Core and CLI while retaining the shell command unchanged.

## Architecture

- Impact: high
- Boundary: `Core Codex activation planner and execution evaluator`
- Boundary: `CLI Codex activation filesystem adapter`
- Contract: `Core deterministically validates adoption and owned-content observations, creates a content-addressed activation plan, and maps immutable mutation and scratch-cleanup observations to stable results without filesystem, process, environment, clock, Git, or network access`
- Contract: `CLI acquires packaged activation bytes and no-follow target observations, creates only private external scratch during preview, revalidates every target precondition before apply, stages every effect beside its destination, applies the activation snapshot last, reverse-recovers detected failure, and reports observations rather than assigning semantic outcomes`
- Contract: `the retained shell activator and TypeScript command agree on preview, apply, unchanged, conflict, safety, recovery, cleanup, generated bytes, owned surface, and exit semantics across the shared activation corpus`
- Owner: `Core Codex activation planner and execution evaluator = ForgeFlow TypeScript Core`
- Owner: `CLI Codex activation filesystem adapter = ForgeFlow TypeScript CLI`

## Error Projection

- Source failure: `invalid source snapshot, adoption or ownership conflict, unsafe or stale target observation, scratch preparation or cleanup failure, staging, replacement, recovery, snapshot invalidation, or cleanup failure`
- Public projection: `ACTIVATION_CONFLICT, ACTIVATION_OPERATION_REFUSED, ACTIVATION_APPLY_FAILED_RECOVERED, ACTIVATION_RECOVERY_INCOMPLETE, ACTIVATION_CLEANUP_INCOMPLETE, or sanitized ERROR with stable issues and documented exit`
- Detail policy: `JSON contains repository-relative managed paths and bounded retained-evidence identifiers only; raw operating-system messages, absolute target or scratch paths, environment values, and payload bytes are not emitted`
- Evidence AC: `AC-006`

## Concurrency

- Contended resource: `managed target directory and leaf type, content, directory membership, and staging namespace between planning and application`
- Linearization point: `successful resolved-root identity check followed by full equality recapture of every plan precondition before the first target directory, stage, or destination mutation`
- Conflict outcome: `ACTIVATION_OPERATION_REFUSED with ACTIVATION_STALE_PLAN, exit 1, and an unchanged target mutation manifest`
- Evidence AC: `AC-003`

## Outputs

- `ACTIVATION_PREVIEW`, `ACTIVATION_APPLIED`, `ACTIVATION_UNCHANGED`,
  `ACTIVATION_CONFLICT`, `ACTIVATION_OPERATION_REFUSED`,
  `ACTIVATION_APPLY_FAILED_RECOVERED`, `ACTIVATION_RECOVERY_INCOMPLETE`,
  `ACTIVATION_CLEANUP_INCOMPLETE`, or typed `ERROR` with its documented exit.
- Human output or one canonical JSON result envelope containing ordered exact
  planned changes and sanitized mutation or retained cleanup evidence.
- On incomplete recovery, every unrecovered managed destination and retained
  sibling recovery directory required for manual restoration.

## Rules

- R1: Core owns adoption and ownership decisions, exact desired bytes and
  checksums, plan identity and ordering, stable outcomes, and evidence. It is
  pure and never performs I/O; the CLI adapter reports facts only.
- R2: The only owned destinations are the bounded ForgeFlow section in
  `AGENTS.md` and `SKILL.md`, `story-development.md`, and
  `.forgeflow-snapshot` beneath `.agents/skills/forgeflow/`. Bytes outside the
  bounded section, including CRLF and a missing final newline, are preserved.
- R3: An unknown integration member, incomplete installed snapshot, ambiguous
  marker, locally edited owned file or block, snapshot identity mismatch,
  invalid adoption marker, unsafe path, or stale plan is refused before target
  mutation. There is no force mode.
- R4: The desired skill rewrites only its Story-development reference to the
  installed local filename. The workflow and agent block preserve packaged
  bytes, and the activation operation never writes the adoption marker or Story
  templates.
- R5: Every payload and original is prepared before the first destination
  rename, every stage is private and beside its destination, and
  `.forgeflow-snapshot` is applied last.
- R6: Detected replacement failure recovers attempted effects in reverse order,
  continues after failed restore, restores prior bytes or absence, and removes
  a snapshot that cannot be trusted. Complete recovery, incomplete recovery,
  and cleanup residue remain distinct exit-1 outcomes.
- R7: Preview and unchanged modes perform zero target mutation. Private
  external scratch is allowed; cleanup failure returns
  `ACTIVATION_CLEANUP_INCOMPLETE` and sanitized retained evidence rather than a
  clean preview or unchanged result.
- R8: Activation uses no network and starts no target-owned process. Packaged
  provenance replaces the legacy source-checkout lookup at the CLI boundary
  without changing generated-byte or result semantics.
- R9: Recovery is best effort, not a cross-file crash-atomic transaction.
  SIGKILL, power loss, unavailable filesystems, and hostile changes after final
  recapture remain documented operational risks.

## Expected Errors

- Invalid arguments return typed `ERROR` and exit `2` without target mutation.
- Adoption or owned-content conflict returns `ACTIVATION_CONFLICT` and exit `1`.
- Invalid packaged source, unsafe managed path, staging collision, or stale plan
  returns `ACTIVATION_OPERATION_REFUSED` and exit `1` without target mutation.
- Preparation failure or replacement failure with complete restoration returns
  `ACTIVATION_APPLY_FAILED_RECOVERED` and exit `1`.
- Failed restore or snapshot invalidation returns
  `ACTIVATION_RECOVERY_INCOMPLETE` and exit `1`, naming unrecovered managed
  destinations and retained recovery evidence.
- Preview, unchanged, or committed-apply cleanup residue returns
  `ACTIVATION_CLEANUP_INCOMPLETE` and exit `1`, never claims clean success, and
  names sanitized retained evidence.
- An unexpected failure outside handled observations returns sanitized `ERROR`
  and exit `3` without raw operating-system diagnostics.
